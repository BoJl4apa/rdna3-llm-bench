# Qwen3.8-27B: MTP vs plain q4_K_M on RDNA3

**TL;DR** — Multi-Token Prediction gives **1.65× decode** (42.1 vs 25.5 tok/s)
on a W7800 at GGUF q4_K_M, and on our 100-problem set it is close to a
*transparent* switch: 54/100 completions byte-identical, 80/100 at ≥0.9
character similarity, identical task outcomes on all three agentic scenarios,
and a pass@1 gap of exactly one problem — which turns out to be a token-cap
artifact, not a quality difference. Also worth knowing before you bench it:
**the plain `qwen3.8:27b` tag *is* the MTP build.**

## The tag trap

`qwen3.8:27b` and `qwen3.8:27b-mtp-q4_K_M` resolve to the **same manifest
digest** (`22130167c4c2`); pulling the MTP tag over an existing `27b` is an
instant no-op with no download. The non-MTP model is a separate tag,
`qwen3.8:27b-q4_K_M` (`25b843619e94`).

```
$ ollama list | grep qwen3.8
qwen3.8:27b-q4_K_M         25b843619e94   17 GB
qwen3.8:27b-mtp-q4_K_M     22130167c4c2   17 GB
qwen3.8:27b                22130167c4c2   17 GB     <- same digest as -mtp
```

So a bench of "qwen3.8:27b" is a bench of MTP whether or not it says so. Ours
was, in the [2026-09 round](2026-09-round.md), before we checked — that table's
qwen3.8 row is the MTP arm.

## Speed

Ollama `0.33.2-rocm`, GGUF q4_K_M, single card, temp 0.2, `num_ctx` 16384,
HumanEval-100 cap 3072. Medians over the 100 problems, from Ollama's native
`eval_count`/`eval_duration`.

| arm | pass@1 | decode tok/s | TTFT ms | completion tok | thinking chars |
|---|---:|---:|---:|---:|---:|
| **MTP** (`27b` = `27b-mtp-q4_K_M`) | 0.98 | **42.1** | 11,068 | 822 | 1,128 |
| plain q4_K_M (`27b-q4_K_M`) | 0.99 | 25.5 | 17,568 | 830 | 1,230 |

**MTP decode advantage: 1.65×.** That independently reproduces the 1.64×
reported for this model on an RTX 4090 with llama.cpp — different vendor,
different backend, same speedup. The two arms emit near-identical token counts
(822 vs 830 median), so this is decode rate, not brevity.

## Output drift — the axis a tok/s number hides

A speculative-decoding-style scheme is only a free win if it produces the same
model's answers. We diffed the two arms problem-for-problem: same prompts, same
temperature, same engine, same cap, so any difference is the arm.

| | |
|---|---:|
| byte-identical completions | **54/100** |
| ≥0.9 character similarity | **80/100** |
| 0.5–0.9 similarity | 19/100 |
| <0.5 similarity | **1**/100 |
| median completion length | 517 vs 531 chars |

The prior report for this model on other hardware was **0/15 identical**, and
concluded MTP is "not a transparent switch". **That does not reproduce here.**
We can't explain the gap from our side — different backend (Ollama/llama.cpp
vs llama.cpp direct), different sampler settings, and 15 samples against 100 —
but on this box, at temp 0.2, the majority of outputs are bit-for-bit the same
and the tail is near-identical.

## The single quality difference is a token cap, not the model

pass@1 differs by exactly one problem, **HumanEval/94** — which is also the
only problem in the set with 0.0 similarity between the arms:

| arm | completion | tokens | thinking chars |
|---|---|---:|---:|
| MTP | *empty* | 3,072 (**at cap**) | 3,933 |
| plain q4_K_M | 1,000 chars, passes | 2,568 | 2,922 |

MTP spent the entire 3072-token budget inside `message.thinking` and emitted no
content — the [thinking-model harness failure](../findings/thinking-models-vs-harnesses.md)
this repo has now documented three times, here reached by a *longer reasoning
trace on the same problem* rather than by a smaller cap. Remove that one
problem and the arms are 98/99 identical in score. Treat them as
quality-equivalent on this evidence; the 0.98 is a cap artifact.

## Agentic lane — indistinguishable

Three scenarios, n=5 runs each, `MAX_TOOL_TURNS=12`, native structured tool
calls. `task_complete` runs out of 5 (see
[the two-modes finding](../findings/two-agentic-modes.md) for what each measures):

| scenario | MTP | plain q4_K_M |
|---|:---:|:---:|
| rename (batching) | 5/5 | 5/5 |
| staged fix-loop | 5/5 | 5/5 |
| diagnosis (read-only) | 5/5 | 5/5 |

Both arms are the strongest agentic profile in the 2026-09 field — the only
models that complete *both* the batching task and the iterative fix-loop. They
differ only in loop termination on the rename scenario (MTP declared itself
done in 1/5 runs, plain q4 in 0/5), which is the completion-vs-convergence
distinction, not a capability gap: both did all 12 edits every time.

## Verdict

On this hardware, MTP is a **1.65× decode speedup at equal quality and equal
agentic behaviour**, and is what you get by default from the `27b` tag. We
found no reason to prefer the non-MTP build.

## Threats to validity

- **n=1 per HumanEval problem, n=5 per agentic scenario, one box.** The 54/100
  identical figure is one temperature (0.2) and one sampler configuration;
  drift at higher temperature is not measured.
- **The 3072 cap shapes the pass@1 comparison**, as the HumanEval/94 case shows
  directly. A larger budget would likely equalize the arms at 0.99.
- **We did not test MTP under concurrency**, where speculative schemes usually
  behave differently from single-stream.
- Both arms are the same weights at the same quant; this compares the decode
  path, not model quality.
